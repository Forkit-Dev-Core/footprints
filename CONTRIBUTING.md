# Contributing to Footprints Discovery

1. Pick an existing issue or open one describing the problem and what a useful result would look like. Comment if you want to take it on so maintainers can avoid duplicate work. Use Discussions for early ideas and questions.
2. Fork the repository if forking is available, or work on a branch in the repository if you already have write access. Keep the change focused on one issue.
3. Use fictional or synthetic evidence in examples and reports. Avoid device logs, local paths, account names, and other private data. Explain any new permissions or network use in your proposal before implementing it.
4. Run `node --test`. For visual changes, open `index.html` and describe what you checked. Open a pull request against `main` and link the issue. A draft is welcome if you want early feedback.

Maintainers use Issues to track actionable work, help contributors scope changes, and merge after review and passing checks. For changes to discovery behavior, reviewers look for a representative match and a near match that should be ignored.

Be respectful and constructive in discussions and reviews. If someone posts private information, flag it for maintainers without quoting it.
